# Onboarding

Five to ten minutes from fork to your first merge-ready feature. Read this once, then keep `README.md` open as the reference.

## 1. What is this?

A forkable pipeline that turns a one-paragraph brief into merge-ready code with tests, ADRs, and security and quality reports. Stages 01–04 produce specifications (idea, PRD and stories, optional UX, architecture). Stage 05 produces code: it scaffolds the app, plans tasks, writes tests first, implements, and runs quality gates. Most stages are AI-driven through Claude Code skills, with human approval gates between them. The pipeline is repo-local — every skill, hook, and validator is vendored under `.claude/` and `pipeline/`, so a fresh fork runs without installing global plugins.

## 2. Install once

Prereqs (full table with rationale lives in `README.md`):

- **Git** — also provides `bash` and `perl` on Windows. https://git-scm.com
- **Node.js 20+** — https://nodejs.org
- **`jq`** — used by the ralph-loop stop hook.
  - Windows: `choco install jq` or `winget install jqlang.jq`
  - macOS: `brew install jq`
  - Linux: `apt install jq`
- **Claude Code CLI** — https://docs.claude.com/code

No global Claude Code plugins required. See `README.md` § "Prerequisites for a forker" for the source-of-truth table.

## 3. Your first feature in 10 minutes

The fastest path is the wizard:

```bash
# a. Fork on GitHub, clone, open Claude Code at the root
gh repo fork kstroz/sdlc --clone
cd sdlc
claude
```

```
# b. Inside Claude Code, run one command:
/start-flow
```

The wizard does the rest: it asks for your JIRA ticket and slug (or generates one), prompts you to paste the brief, multi-selects which platforms you are building (iOS / Android / cross-platform mobile / web / backend / desktop / cli), and only asks per-platform tech questions for the platforms you picked (e.g. "iOS UI: SwiftUI or UIKit?", "Backend: Node, Python, Go, or let architect decide?"). It writes `_inputs/stack-preferences.md` and runs `/stage-01` for you.

Re-run `/start-flow` after each stage and it advances to the next one — or call `/stage-XX` directly when you want fine-grained control.

After the plan gate (Stage 05.1 produces `plan.md` and stops), commit `_approval-plan.json`, then start the autonomous implementation loop:

```
/ralph-loop "Apply skill: running-impl-loop" --completion-promise "MERGE-READY" --max-iterations 50
```

The loop drives 05.2 → 05.8 (tests-plan, TDD impl, four quality reports, security review, code review, changelog) and emits `<promise>MERGE-READY</promise>` only when `check-merge-readiness.sh` exits 0. Then commit `_approval-merge.json` and the branch is ready to merge.

(Stage 03 is optional; skip it for non-UI features. Stage 05 itself runs `05.0 bootstrap` and `05.1 plan`, then stops at the plan gate.)

```bash
# e. Inspect the plan, then approve it
$EDITOR .pipeline/05-dev/plan.md
cat > .pipeline/05-dev/_approval-plan.json <<'JSON'
{ "decision": "approved", "approver": "you", "date": "2026-05-08" }
JSON
git add .pipeline/05-dev/_approval-plan.json && git commit -m "approve plan"
```

```
# f. Start the autonomous implementation loop
/ralph-loop "Apply skill: running-impl-loop" --completion-promise "MERGE-READY" --max-iterations 30

# g. When the loop emits MERGE-READY, run the human-gate review
/review-pr
```

## 4. Where things live

- `.claude/skills/` — the 12 Phase 2 skills + vendored TDD/debugging/verification skills.
- `.claude/commands/` — slash commands `/stage-01..05`, `/ralph-loop`, `/review-pr`, `/cancel-ralph`.
- `.claude/hooks/stop-hook.sh` — ralph-loop stop hook (vendored, no global plugin needed).
- `.claude/PROGRESS.md` — the loop reads this to know its phase.
- `pipeline/conventions/` — source of truth for every artifact's shape.
- `pipeline/validators/` — bash validators that gate every stage; their exit code is the truth.
- `.pipeline/` — generated per feature branch; never on `main`.
- `app/` — generated by `05.0 bootstrap` from your `tech-stack.md`.

Full layout in `README.md` § "Repo layout".

## 5. Common stumbles

- **`jq: command not found`** during the ralph-loop stop hook → install `jq` (see § 2), then fully restart Claude Code so it picks up the new PATH.
- **Bash on Windows** → use **Git Bash**, not WSL. The validators and `init-project.sh` assume Git for Windows' bash; WSL paths break the `.pipeline/` references.
- **Validator FAIL with a `grep` core dump** → known issue, fix is on the backlog. Re-run the validator; if it persists, narrow the input file passed to it.
- **`/ralph-loop` won't stop** → run `/cancel-ralph` from the same Claude Code session.
- **Skills don't autoload after editing `.claude/skills/`** → run `/reload-plugins`.

## 6. Where to ask

Open a GitHub issue on your upstream of `kstroz/sdlc`. Before filing, confirm the failing validator and paste its output — agent self-assessment doesn't count, validators do.

This repo is **forkable by design**: don't push fixes or experiments to the upstream. Fork first, change in your fork, then send a PR upstream if it's a general improvement.

## Appendix: walking through the BAJ-100 example

### What is BAJ-100?

BAJ-100 is a synthetic test feature for a maintenance technician mobile app, used as the canonical example shipped with this repo. It exists to validate the pipeline end-to-end so you can read the artifacts in order without running the agents yourself.

### The artifacts produced

- `.pipeline/01-idea/_inputs/brief.md` — initial brief from the (synthetic) client.
- `.pipeline/01-idea/_inputs/interview-2026-05-08.md` — synthetic kickoff interview transcript.
- `.pipeline/01-idea/idea.md` — the I-001 idea with hypothesis and success criteria.
- `PRODUCT.md` — 2 personas (Marek, Tomasz) and 4 glossary terms.
- `.pipeline/02-spec/prd.md` — 5 epics (E-01..E-05) and 6 NFRs.
- `.pipeline/02-spec/stories/US-001..US-013` — 13 user stories covering the epics.
- `.pipeline/04-architecture/{tech-stack, data-model, api-contracts, architecture}.md` plus `adr/ADR-001..ADR-006` — full Stage 04 output.
- `.pipeline/05-dev/plan.md` plus `tasks/T-001..T-010` — 10 implementation tasks.
- `app/` — bootstrapped Expo app with the sanity test passing.

### Try it yourself

1. Run `bash scripts/smoke-test.sh` to see all validators pass green against the committed artifacts.
2. Open `.pipeline/02-spec/prd.md` to see the epics table and how stories trace back to it.
3. Open `.pipeline/05-dev/plan.md` to see the task plan and how each `T-NNN` references its upstream stories.

### What is NOT yet done

- `tests-plan.md`, quality reports, security review, code review, and changelog are not in the example. These are produced by the autonomous loop after the user commits `_approval-plan.json`.
